How the math works

This is an idealized roofline analysis. It models the upper bound on performance from two resources — tensor-core compute and HBM bandwidth — and ignores communication, kernel-launch, and software overhead.

FLOPs(prefill) = B·S·2·N_active + 2·B·S²·L·(H + H_kv)
FLOPs(decode/token) = 2·N_active + 2·L·S·(H + H_kv)
DRAM bytes(prefill) = W + B·S·(2·L·H_kv·b_kv + 16·H)
DRAM bytes(decode/step) = W + B·(2·L·S·H_kv·b_kv + 2·L·H_kv·b_kv + 16·H)
Arithmetic intensity I = FLOPs / DRAM bytes
Achieved = min(compute peak, bandwidth × I)
Ridge point = compute peak / bandwidth

Where N_active is active parameters (MoE models use only their per-token active experts), W is weight bytes, H hidden size, H_kv KV-head dimension (GQA shrinks the KV cache), L layers, S sequence length, B batch size. The 16·H per-token term is a rough activation-traffic estimate. Memory capacity includes weights, KV cache, and a FlashAttention-style activation buffer estimate of 16·B·S·H bytes. Multi-GPU results assume ideal tensor-parallel scaling with weights and KV sharded across GPUs.
